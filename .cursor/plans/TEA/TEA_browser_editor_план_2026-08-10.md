# План создания браузерного TEA-редактора (frontend-only, single-file)

## Как отмечать прогресс

- `[ ]` - не начато
- `[~]` - в работе
- `[x]` - завершено
- Сначала закрываются подзадачи, затем задача, затем этап.

---

## 1) Принятая модель

Целевой сценарий:
- открыть страницу web-версии TEA (локально или на сервере);
- выбрать **один** файл сценария (`.json`);
- редактировать его в браузере;
- сохранить через `Save` / `Save As`.

Архитектурные решения:
- **только frontend** (без backend, без серверного API);
- вся доменная логика (шаблоны, валидация, граф, локализация, контракты) вшита в клиентский код;
- одновременно редактируется только один загруженный adventure-файл;
- нет файлового менеджера и нет CRUD по списку adventure-файлов.

Критерии общего успеха:
- [ ] страница работает локально (открытие из папки / static host);
- [ ] страница работает после публикации на любом static-сервере;
- [ ] выбранный JSON можно загрузить, отредактировать, провалидировать и сохранить;
- [ ] формат JSON совместим с runtime TEA;
- [ ] поток "открыл страницу -> выбрал файл -> работаешь" полностью закрыт.

## 3) Ограничения браузера (обязательно учитывать)

### 3.1 Что браузер умеет
- [ ] Чтение выбранного пользователем файла через File API.
- [ ] Скачивание результата через `Blob` + `download` (`Save As`).
- [ ] В Chromium-based браузерах: запись в тот же файл через File System Access API (`showSaveFilePicker` / `createWritable`).

### 3.2 Чего браузер не умеет без backend
- [ ] Не имеет произвольного доступа к файловой системе проекта.
- [ ] Не может сам "найти" adventure в `Assets/...`.
- [ ] Не может атомарно обновлять файл вне явно выбранного пользователем handle.
- [ ] Не может гарантировать запись "поверх того же пути" во всех браузерах (Firefox/Safari обычно только `Save As`/download).

### 3.3 UX-правила из ограничений
- [ ] Основной путь сохранения: `Save As` (скачивание обновленного JSON).
- [ ] Если доступен File System Access API: показывать полноценный `Save` в исходный файл.
- [ ] Если API недоступен: `Save` либо скрыт, либо работает как `Save As`.
- [ ] После `Open File` хранить в сессии имя файла и (если есть) file handle.
- [ ] Явно показывать пользователю текущий режим сохранения (`Same file` / `Download only`).
